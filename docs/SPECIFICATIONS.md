# BT RSSI Tracer 仕様書

この文書は、BT RSSI Tracer の確定済み仕様を実装可能な形で記録する。
未記載の動作は未決定として扱い、参考アプリや旧実装から暗黙に補完しない。

## 1. デバイス検出

### 1.1 目的

ユーザーが明示的に操作した場合だけ Bluetooth Classic の周辺デバイス探索を行い、今回の探索セッションで検出した端末から測定対象を選択できるようにする。

### 1.2 起動条件

- デバイス選択を開始するボタンの表示名は `TARGET` とする。
- アプリ起動時にはデバイス探索を開始しない。
- ユーザーが `TARGET` ボタンを押したときに、端末選択ダイアログを開いて新しい探索を開始する。

### 1.3 一覧の初期状態とデータ源

- ダイアログを開くたびに、端末一覧を空の状態で新規作成する。
- 前回の探索結果は再利用、復元、キャッシュ表示しない。
- ペアリング済み端末を一覧の初期値として取得・表示しない。
- 一覧に表示できるのは、現在の探索セッション中に実際に検出された端末だけとする。

### 1.4 探索中の更新

- 探索中に端末を検出したら、ダイアログを閉じたり探索完了を待ったりせず、検出の都度一覧へ反映する。
- 一覧はダイアログを表示したままリアルタイムに更新する。
- 端末は最初に検出した順序で上から並べる。
- 新しく検出した端末は、既存の並び順を変更せず一覧の末尾へ追加する。
- 同一端末の判定にはBDアドレスを使用し、再検出時に同じ端末を別の行として追加しない。
- 同一端末を再検出したときは、新しいRSSIが現在の表示値より数値として大きい場合だけRSSI表示を更新する。例えば `-50 dBm` は `-70 dBm` より大きい値として扱う。
- RSSIを更新しても、その端末の表示順は変更しない。

一覧の各行には、次の項目を表示する。

1. デバイス名
2. BDアドレス
3. Bluetooth TYPE
4. Bluetooth Class
5. RSSI（単位表記は `dBm`）

- 一覧行は2行構成を維持し、高さを `56dp` 以上とする。
- 行内の上下余白は、操作性と視認性を保ちながら一覧の表示件数を増やせるよう適度に詰める。
- 左列は1行目にデバイス名、2行目にBDアドレスを表示する。
- その右の列は1行目にBluetooth TYPE、2行目にBluetooth Classを表示し、さらに右側へRSSIを表示する。
- Bluetooth TYPEは `BluetoothDevice.getType()` の結果を `CLASSIC`、`LE`、`DUAL`、`UNKNOWN` のいずれかで表示する。
- ダイアログ内のBluetooth TYPEには `Type:` の接頭辞を付けない。
- Bluetooth ClassはInquiry結果のClass of Deviceから大分類を読み取り、`Audio/Video` のような短い英語表記とする。
- ダイアログ内では文字数を抑えるため、Bluetooth Classに `Class:`、RSSIに `RSSI:` の接頭辞を付けない。
- Bluetooth Classを取得または判別できない場合は `Unknown` と表示する。

デバイス名を取得できない場合は、デバイス名欄に短い代替表記として `Unknown` を表示する。

#### Classic Onlyフィルター

- ダイアログ内の探索状態表示の右側（右上）に `Classic Only` チェックボックスを表示する。
- 初回はONとし、変更した状態は保存してダイアログ再表示・アプリ再起動後も反映する。
- ONではTYPEが `CLASSIC` の端末のみ表示する。`DUAL`、`LE`、`UNKNOWN` は表示しない。OFFでは全TYPEを表示する。
- フィルターに関係なく、今回の探索で検出した全端末とRSSIを内部で保持する。ON/OFF切り替えは探索を再開せず、表示だけを即座に更新する。
- 全端末の初回検出順を保持し、切り替え後もその順序で表示する。非表示だった端末は元の位置に戻す。
- 探索停止後もダイアログが開いていればフィルターを切り替えられる。ダイアログ終了時には従来どおり探索結果を破棄する。

### 1.5 探索の終了条件

次のいずれかが発生した時点で、進行中の探索を即座に停止する。

1. ユーザーが一覧から端末を選択した。
2. ユーザーがキャンセル、戻る操作、ダイアログ外タップなどで端末選択ダイアログを閉じた。
3. 探索開始から60秒が経過した。

端末選択時は、探索停止後に選択した端末を測定対象として保持する。ダイアログを選択せずに閉じた場合は、その探索セッションの一覧を破棄する。

探索時間の上限は1回につき60秒とする。60秒へ到達した場合は探索だけを停止し、検出済みの一覧とダイアログは表示したままにする。

### 1.6 探索状態の表示

- 探索中は、端末選択ダイアログ内に `SCANNING...` と進行中であることが分かるインジケーターを表示する。
- 端末の一覧表示と探索中表示は同時に確認できるようにする。
- 端末選択、ダイアログ終了、または60秒経過により探索が停止したら、探索中表示も停止する。
- 60秒経過時は探索中表示を非表示にするが、その表示領域の高さは維持し、ダイアログと一覧を再配置しない。
- 探索が完了しても、完了メッセージや完了ラベルは表示しない。
- 探索中に端末を1台も検出しなかった場合も、空状態用のメッセージは表示せず、一覧を空欄のままにする。

### 1.7 権限処理

権限処理の構造とユーザーへの案内方法は、参考アプリ RF Monitor の実装方針に合わせる。

- Bluetooth関連権限の確認と要求処理を一か所へ集約する。
- 必要な権限がない場合は、権限要求の結果が返るまで探索を開始しない。
- Android 12（API 31）以降では、少なくとも `BLUETOOTH_SCAN` と `BLUETOOTH_CONNECT` を要求する。
- Android 11（API 30）以前では、Bluetooth探索に必要な位置情報権限を要求する。
- 権限が許可された場合だけ端末選択ダイアログを表示して探索を開始する。
- 権限が拒否された場合は探索を開始せず、権限が必要であることを画面上の案内とToastで通知する。
- 権限不足や `SecurityException` によってアプリが終了しないようにする。
- 権限がない間は測定開始操作を無効化する。`TARGET` は再要求または設定変更後の再試行に使用できる状態を維持する。

### 1.8 Bluetooth無効時の動作

- `TARGET` 押下時にBluetoothが無効なら、端末選択ダイアログおよび探索を開始しない。
- BluetoothをONにする必要があることをユーザーへメッセージで通知する。
- ユーザーがBluetoothを有効にした後、`TARGET` を再度押すことで探索を開始できるようにする。

### 1.9 選択済み端末の表示

参考アプリ RF Monitor の接続端末表示と同じ構成にする。

- メイン画面上部の `TARGET` ボタンの横に、選択した端末の情報を表示する。
- 1行目にデバイス名と `Type: <Bluetooth TYPE>`、2行目にBDアドレスと `Class: <Bluetooth Class>` を横並びで表示する。
- デバイス名を取得できない場合は `Unknown` と表示する。
- `TARGET` を再度押すと新しい空の一覧で探索を開始し、別の端末を選択できる。
- 未保存データがあり `STOP/SAVE` ボタンが `SAVE` の状態で別のターゲット端末を選択した場合は、その時点で未保存データの保存権を破棄し、ボタン表示を `STOP` に戻す。
- ターゲット再選択時点では、直前のグラフと測定値表示は消去しない。これらは次回の `START` 押下時にリセットする。

### 1.10 基本フロー

```text
アプリ起動
  └─ 自動探索しない

TARGET押下
  ├─ Bluetoothが無効ならONにするよう通知して終了
  ├─ 必要な権限を確認
  ├─ 権限不足なら要求し、結果を待つ
  └─ 権限あり
       ├─ 新しい空の端末一覧を作成
       ├─ 端末選択ダイアログを表示
       ├─ SCANNING...を表示
       └─ Bluetooth探索を開始
            └─ 検出した端末を随時一覧の末尾へ追加

端末選択
  ├─ 探索を即時停止
  ├─ 選択端末を測定対象として保持
  ├─ メイン画面に端末名とBDアドレスを表示
  └─ ダイアログを閉じる

選択せずダイアログを閉じる
  ├─ 探索を即時停止
  └─ 今回の一覧を破棄
```

### 1.11 受け入れ条件

- アプリを起動しただけでは Bluetooth 探索が始まらない。
- `TARGET` 押下直後の一覧は空であり、ペアリング済み端末が自動表示されない。
- 探索で検出された端末が、探索中のダイアログへ順次表示される。
- 新規端末は検出順に一覧の末尾へ追加され、既存端末の順序が変化しない。
- 同じBDアドレスの端末は複数行にならず、より大きいRSSIを検出した場合だけ表示値が更新される。
- 各行にデバイス名、BDアドレス、Bluetooth TYPE、Bluetooth Class、RSSIと `dBm` 単位が指定位置で表示される。
- ダイアログではBluetooth TYPEがClassの上に接頭辞なしで表示される。
- 名前を取得できない端末は `Unknown` と表示される。
- 探索中はダイアログ上で探索中であることを確認できる。
- 探索開始から60秒以内に探索が停止する。
- 探索完了時に完了メッセージが表示されない。
- 端末を検出しなかった場合は、ダイアログの端末一覧が空欄のままになる。
- ダイアログを開き直すと、前回の端末一覧が表示されない。
- 端末選択後に探索が継続しない。
- 端末を選択せずダイアログを閉じた場合も探索が継続しない。
- 選択後はメイン画面の `TARGET` 横にデバイス名、BDアドレス、`Type: <Bluetooth TYPE>`、`Class: <Bluetooth Class>` が2行で表示される。
- 権限要求中または権限拒否状態では探索を開始しない。
- Bluetoothが無効な状態で `TARGET` を押すと、探索せずBluetoothをONにするよう案内される。

### 1.12 未決定事項

現時点で、デバイス検出に関する未決定事項はない。

## 2. メイン画面レイアウト

### 2.1 基本方針

- メイン画面は、参考アプリ RF Monitor と同様の縦一列の測定ダッシュボードとする。
- 画面遷移せず、対象端末、グラフ、測定値、測定条件、操作ボタンを1画面で確認・操作できる構成とする。
- 各要素は、以下に定義する順序を変更せず上から配置する。
- RF Monitorより表示要素が少ないことによって生じる余白は、既存要素を過度に拡大して埋めず、将来の表示要素追加に使用できる領域として残す。

### 2.2 配置順序

```text
BT RSSI Tracer  <Androidデバイス名>
────────────────────────────────────────
TARGET  <ターゲット端末名>
        <BDアドレス>
────────────────────────────────────────
              RSSIグラフ
────────────────────────────────────────
RSSI: xx, Min: yy, Max: zz, Avg: aa.a
────────────────────────────────────────
        <将来拡張用の可変空白領域>
────────────────────────────────────────
Delay [sec]              Duration [sec]
<選択UI>                 <選択UI>
────────────────────────────────────────
START                    STOP / SAVE
```

### 2.3 アプリ名とアイコン

- 画面最上部には、アプリタイトル `BT RSSI Tracer` と、アプリを実行しているAndroid端末の名前を表示する。
- 表示方法は参考アプリ RF Monitor と同様に、ActionBarのタイトルへアプリ名、メーカー名、モデル名を同一行で連結する。
- 表示形式は `BT RSSI Tracer <Build.MANUFACTURER> <Build.MODEL>` とする。
- ランチャーアイコンは、RF Monitorと共通の白いBluetoothマークと電波のモチーフを使用する。
- RF Monitorと識別できるよう、背景色はティール `#008C8C` とする。

### 2.4 ターゲット端末

- `TARGET` ボタンを画面上部に配置する。
- ボタンの横に、選択済みターゲット端末の情報を2行で表示する。
- 1行目はターゲット端末名と `Type: <Bluetooth TYPE>`、2行目はBDアドレスと `Class: <Bluetooth Class>` とする。
- 端末名を取得できない場合は `Unknown` と表示する。
- `TARGET` 押下時の端末選択動作は「1. デバイス検出」に従う。

### 2.5 RSSIグラフ

- ターゲット端末欄の下にRSSIグラフを配置する。
- 描画ライブラリ、基本的な外観、凡例、リアルタイム更新、横スクロールおよびタップによる表示範囲切り替えは、参考アプリ RF Monitor のRSSIグラフを踏襲する。
- BT RSSI Tracerでは、選択したターゲット端末のRSSIを単一系列として描画する。
- 縦軸は手動範囲とし、最小値を `-100`、最大値を `0` とする。
- 縦軸の数値目盛りは表示するが、縦軸タイトルは表示しない。
- 凡例は `RSSI [dBm]` と表示する。
- 横軸には測定開始からの経過時間を秒単位で使用する。
- 横軸の数値目盛りはプロット領域の下端に配置し、上端の `Y=0` 線は強調しない。
- RF Monitorと同じ `FramedGraphView` の設計を使用し、プロット領域の四辺を均一な `2dp` の太線で囲む。枠色はテーマの横軸ラベル色に合わせ、サイズ変更および保存PNGにも反映する。
- 横軸のタイトルは `Time [sec]` とし、単位が秒であることをグラフ上に表示する。
- 横軸の数値目盛りと軸タイトルの間には、横軸文字サイズの約0.5行分のクリアランスを設け、文字同士を接触させない。
- グラフ描画領域の左右には、端の横軸目盛りが画面外へ欠けないだけの内部余白を確保する。

### 2.6 測定値表示

- RSSIグラフの下に、測定値を1行のテキストとして表示する。
- 表示形式は次のとおりとする。

```text
RSSI: xx, Min: yy, Max: zz, Avg: aa.a
```

- `RSSI` は最新の測定値とする。
- `Min`、`Max`、`Avg` は現在の測定セッションで取得したRSSIから算出する。
- `Avg` は小数第1位まで表示する。
- 測定開始前は、プレースホルダーや初期値を表示せず空欄とする。

### 2.7 測定条件

- 測定値表示の下に、`Delay [sec]` と `Duration [sec]` の選択UIを横並びで配置する。
- 各ラベルの下に対応する選択UIを配置する。
- DelayとDurationの行はSTARTおよびSTOP/SAVEと一つの下部操作ブロックを構成し、画面下側へ配置する。
- `Period` の選択UIは設けない。
- Delayの選択肢は、参考アプリ RF Monitor と同じ `0`、`1`、`2`、`5`、`10` 秒とする。
- Delayの初期値は `0` 秒とする。
- Durationの選択肢は、参考アプリ RF Monitor と同じ `5`、`10`、`20`、`30`、`40`、`50`、`60`、`100`、`120` 秒、および無制限を表す `inf` とする。
- Durationの初期値は `inf` とする。

### 2.8 操作ボタン

- 画面下部に `START` ボタンと、単一の `STOP/SAVE` ボタンを横並びで配置する。
- 2つのボタンは同じ幅を基本とする。
- 2つのボタンの高さはRF Monitorと同じく、実行端末の画面ピクセル高さの7.5%とする。
- `STOP/SAVE` ボタンは測定・保存状態に応じて表示ラベルと役割を切り替える。

ボタンと測定条件UIの状態遷移は、参考アプリ RF Monitor に準じて次のようにする。

| 状態 | START | STOP/SAVE | TARGET | Delay/Duration |
| --- | --- | --- | --- | --- |
| ターゲット未選択、権限不足、またはBluetooth利用不可 | 無効 | 無効・`STOP` | 有効 | 有効 |
| ターゲット選択済み・測定待機 | 有効 | 有効・`STOP` | 有効 | 有効 |
| Delay待機中または測定中 | 無効 | 有効・`STOP` | 無効 | 無効 |
| 測定停止後・未保存データあり | 有効 | 有効・`SAVE` | 有効 | 有効 |
| 保存完了後 | 有効 | 有効・`STOP` | 有効 | 有効 |

- `START` を押すと新しい測定セッションを開始し、前回のグラフ、統計値、測定データ、保存済み状態をリセットする。
- Delay待機中に `STOP` を押した場合も、待機をキャンセルして測定待機状態へ戻す。
- 測定中に `STOP` を押すと測定を停止する。保存可能な測定データが存在する場合は、同じボタンの表示を `SAVE` に変更する。
- Duration満了による自動停止も、`STOP` 押下時と同じ停止後状態へ移行する。
- `SAVE` を押すと現在の測定データを保存し、保存成功後にボタン表示を `STOP` へ戻す。
- 同一測定セッションのデータを重複保存しない。
- 保存対象データが存在しない場合は `SAVE` 状態へ移行しない。
- `SAVE` 状態で別のターゲット端末を選択した場合は、未保存データを破棄扱いにして `STOP` 表示へ戻す。保存を確認するダイアログは表示しない。

### 2.9 縦方向の領域配分

- アプリタイトル、ターゲット端末、RSSIグラフ、測定値表示は画面上側から順に配置する。
- 測定値表示と下部操作ブロックの間には、残りの高さを受け持つ可変空白領域を設ける。
- 可変空白領域には、現時点では文字、枠、プレースホルダーなどを表示しない。
- RSSIグラフや測定値表示を、余白を埋める目的だけでRF Monitorより不自然に縦へ拡大しない。
- Delay、Duration、START、STOP/SAVEを含む下部操作ブロックは、画面下端へフィットさせる。
- 下部操作ブロックは、ナビゲーションバーやジェスチャー領域などのシステムインセットと重ならないように配置する。
- 画面サイズやシステムインセットが異なる端末でも、下部操作ブロック全体が欠けずに操作できるようにする。
- 将来要素を追加する場合は、原則としてこの可変空白領域を使用し、下部操作ブロックの位置と操作性を維持する。

### 2.10 受け入れ条件

- 画面要素が「タイトル、ターゲット端末、RSSIグラフ、測定値、測定条件、操作ボタン」の順に並ぶ。
- タイトルに `BT RSSI Tracer` と実行中のAndroid端末情報が表示される。
- `TARGET` の横に、選択端末名とBDアドレスが2行で表示される。
- RSSIグラフの縦軸が `-100` から `0` の範囲になる。
- 縦軸タイトルが表示されず、凡例が `RSSI [dBm]` と表示される。
- 横軸の右端目盛りが画面端で欠けずに表示される。
- 測定値が指定された1行形式で表示され、平均値が小数第1位になる。
- 測定開始前は測定値表示が空欄になる。
- `Delay [sec]` と `Duration [sec]` の選択UIがあり、`Period` の選択UIが存在しない。
- Delayの初期値が `0`、Durationの初期値が `inf` になる。
- `START` と単一の `STOP/SAVE` ボタンが横並びになる。
- `START` と `STOP/SAVE` の高さが等しく、RF Monitorと同じ画面高さ比率になる。
- Delay、Duration、START、STOP/SAVEが画面下側にまとまって表示される。
- 測定値表示と下部操作ブロックの間に、何も表示しない将来拡張用の余白が確保される。
- 下部操作ブロックがシステムUIと重ならず、全操作部品が画面内に収まる。
- Delay待機中と測定中は、START、TARGET、Delay、Durationを操作できない。
- 測定停止後に未保存データがある場合だけ、ボタン表示が `SAVE` になる。
- 保存成功後はボタン表示が `STOP` に戻り、同じデータを再保存できない。
- 未保存状態で別のターゲットを選ぶと、確認操作なしで `SAVE` が `STOP` に戻り、直前のデータを保存できなくなる。

### 2.11 未決定事項

## 3. データ保存

### 3.1 保存契機と成果物

- 保存処理は、`STOP/SAVE` ボタンが `SAVE` 状態のときにユーザーが押した場合に実行する。
- 1回の保存操作で、測定データのCSVファイルと、保存時点の画面スクリーンショットのPNGファイルを保存する。
- CSVとPNGには同じベースファイル名を使用する。
- 同一測定セッションに対する重複保存は行わない。
- CSVはUTF-8で出力する。

### 3.2 保存場所とAndroidバージョン対応

- 保存先は、ユーザーが参照できる共有ストレージの `Documents` とする。
- `Documents` の直下にアプリ専用サブディレクトリ `BT_RSSI_Tracer` を作成し、CSVとPNGをその中へ保存する。
- 保存先の論理パスは `Documents/BT_RSSI_Tracer` とする。
- Android 10（API 29）以降では、参考アプリ RF Monitor と同様にMediaStoreとScoped Storageを使用する。
- Android 9（API 28）では、参考アプリ RF Monitor と同様に従来の共有外部ストレージAPIとストレージ権限を使用する。
- MediaStoreへの保存に失敗した場合は、不完全なエントリを残さない。

### 3.3 ファイル命名規則

参考アプリ RF Monitor の命名規則に準じ、ターゲット端末名とミリ秒までの保存日時を組み合わせる。

```text
<ターゲット端末名>_yyyyMMdd_HHmmss_SSS.csv
<ターゲット端末名>_yyyyMMdd_HHmmss_SSS.png
```

- CSVとPNGで、ターゲット端末名およびタイムスタンプが一致するようにする。
- ターゲット端末名に含まれるスペースは `_` に置換する。
- 端末名を取得できない場合は `Unknown` を使用する。

### 3.4 RF Monitorと現行BT RSSI Tracerのデータ形式比較

以下は、新しいCSV仕様を決定するための比較であり、新アプリのCSV列仕様を確定するものではない。

| 項目 | 参考アプリ RF Monitor | 現行BT RSSI Tracer |
| --- | --- | --- |
| ファイル形式 | CSV | 独自の空白区切りTXT |
| 保存操作 | 測定停止後にユーザーが `SAVE` | 指定測定時間の終了時に自動保存 |
| ファイル名 | `<端末名>_yyyyMMdd_HHmmss_SSS.csv` | `yyyyMMdd_HHmmss.txt` |
| 保存場所 | 共有 `Documents/RF_Monitor` | アプリ専用外部領域の `Documents` |
| 文字コード | UTF-8を明示 | `FileWriter` の既定文字コード |
| 測定メタデータ | CSV内には保存しない | メモ、Android端末名、Androidバージョン、ターゲット端末名、BDアドレス、測定時間を先頭へ保存 |
| 時間単位 | 秒 | ミリ秒 |
| データ系列 | Agent/PartnerそれぞれのPeer RSSI、Phone RSSI、Peer Error、ACL Error | 選択した1端末のRSSIのみ |
| データ列数 | Agent 5列＋Partner 5列の合計10列 | 経過時間とRSSIの2項目 |
| 行の対応 | AgentとPartnerの同じ配列インデックスを同一行へ結合 | RSSI検出1回につき1行 |
| スクリーンショット | CSVと同名のPNGを保存 | 保存しない |

RF MonitorのCSVヘッダーは、左右情報を含めて概ね次の構成になっている。

```text
A Time,A PeerRssi,A PhoneRssi,A PeerErr,A AclErr,
P Time,P PeerRssi,P PhoneRssi,P PeerErr,P AclErr
```

現行BT RSSI Tracerの保存内容は概ね次の構成になっている。

```text
<メモ>
ModelName: <Android端末名>
Android <バージョン>
TargetDevice: <ターゲット端末名>
Address: <BDアドレス>
TraceTime: <測定時間>sec
time[ms] RSSI[dBm]
<経過時間ms> <RSSI>
```

### 3.5 新アプリのCSV形式

- CSVは、経過時間とRSSIだけを持つ2列の表形式とする。
- ヘッダーは `Time [sec],RSSI [dBm]` とする。
- `Time [sec]` には測定中の経過時間を秒単位で記録する。
- 秒の値はミリ秒相当の精度を保持できるよう、小数第3位まで出力する。
- `RSSI [dBm]` には各検出時点のRSSIを整数で記録する。
- CSVにはメタデータ、コメント行、空行などの前置き情報を含めない。
- Android端末名、ターゲット端末名、BDアドレス、測定条件、統計値などのメタデータはCSVへ保存しない。

出力例は次のとおりとする。

```csv
Time [sec],RSSI [dBm]
0.000,-65
1.241,-67
2.518,-64
```

### 3.6 スクリーンショットの役割

- CSVへ含めない測定メタデータは、同時保存する画面スクリーンショットで確認できるようにする。
- スクリーンショットには、保存時点のアプリタイトル、Android端末情報、ターゲット端末名、BDアドレス、RSSIグラフ、測定統計値、Delay、Durationが画面上に表示されていることを前提とする。
- CSVとPNGの対応は、同一のベースファイル名によって識別する。

### 3.7 受け入れ条件

- 保存されたCSVとPNGが `Documents/BT_RSSI_Tracer` に存在する。
- CSVの先頭行が `Time [sec],RSSI [dBm]` になる。
- CSVの各データ行が、経過秒とRSSIの2列だけで構成される。
- CSVに端末情報や測定条件などのメタデータが含まれない。
- 同じ保存操作で生成したCSVとPNGのベースファイル名が一致する。
- PNGから、CSVへ含めなかった端末情報、測定条件、グラフおよび統計値を確認できる。

### 3.8 保存結果の表示

- 保存成功時の保存先表示は、参考アプリ RF Monitor の方式に準ずる。
- CSVの保存成功後、画面上部のToastで `Saved: Documents/BT_RSSI_Tracer/<CSVファイル名>` と表示する。
- CSVの保存に成功した場合だけ、対応するスクリーンショットPNGの保存を実行する。
- 保存に失敗した場合は、成功時の保存先を表示せず、失敗したことをToastで通知する。

### 3.9 未決定事項

現時点で、データ保存に関する未決定事項はない。

## 4. 測定実行とライフサイクル

### 4.1 バックグラウンド測定

- `START` によって開始したRSSI測定は、アプリのメイン画面がバックグラウンドへ移行した後も継続する。
- Delay待機中にバックグラウンドへ移行した場合も、Delay経過後に測定を開始する。
- バックグラウンド測定は、ユーザーが `STOP` を押すか、有限のDurationが満了するまで継続する。
- 測定処理と測定データはActivityではなくフォアグラウンドサービスが所有し、測定中はAndroidの継続通知を表示する。
- 測定中は必要な期間だけCPUのスリープを防ぐ仕組みを使用し、測定停止時に必ず解除する。
- バックグラウンド中に取得した測定データも、フォアグラウンド中のデータと同じCSV、統計およびグラフの対象にする。
- アプリがフォアグラウンドへ戻ったときは、サービスが保持している最新の測定状態、統計値および全プロットデータを画面へ反映する。

### 4.2 TARGET探索とバックグラウンド移行

- `TARGET` から開始する端末選択用の探索は、メイン画面がバックグラウンドへ移行した時点で即座に停止する。
- バックグラウンド移行時に端末選択ダイアログが開いている場合は、ダイアログを閉じず、検出済み一覧も破棄しない。
- フォアグラウンドへ戻ったときは、停止時点のダイアログと検出済み一覧をそのまま表示する。
- アプリがフォアグラウンドへ戻っても、TARGET探索を自動再開しない。
- 再探索には、ユーザーによる `TARGET` の再押下が必要とする。
- TARGET探索の停止は、すでにSTART済みのバックグラウンド測定を停止させない。

### 4.3 `startDiscovery()` による非周期サンプリング

- RSSIの取得にはターゲット端末のTYPEによる方式分岐を設けず、従来どおり `BluetoothAdapter.startDiscovery()` の検出結果を使用する。
- `startDiscovery()` が同時に取得するClassic Inquiry結果とLE Scan結果を区別せず、選択済みBDアドレスと一致する検出結果を測定対象とする。
- 検出処理の性質上、RSSIデータの取得周期は固定値として保証しない。
- `Period` 設定、固定間隔タイマー、補間値によって疑似的に等間隔データを作らない。
- 測定中にターゲット端末からの検出応答を受信したら、その時点のRSSIと実際の経過時間を直ちに測定データへ追加する。
- 追加した測定値は、受信の都度リアルタイムに統計値とグラフへ反映する。
- ターゲット端末の応答を処理したら、そのDiscoveryを停止して次のDiscoveryを開始し、次の検出機会を待つ。
- 次の応答を取得するため、測定中はDiscoveryを必要に応じて繰り返す。
- 1回のDiscoveryがターゲット未検出で終了した場合も、測定停止条件へ到達していなければ次のDiscoveryを開始する。
- 各データ点の横軸値とCSVの `Time [sec]` には、固定周期から算出した値ではなく、実際に応答を受信した時刻に基づく経過秒を使用する。

### 4.4 Bluetoothリソースの解放

- Bluetoothアダプター自体をアプリからOFFにはしない。
- アプリが所有する探索、Receiver、コールバック、Handler、WakeLock、サービスおよびその他のBluetooth関連リソースを、不要になった時点で確実に解放する。
- 解放処理は複数回呼ばれても問題が起きないよう、登録状態と実行状態を追跡して冪等に実装する。
- TARGET探索の終了時は、端末選択用のInquiry、タイムアウト処理およびReceiverを解放する。
- 測定停止時は、測定用Inquiry、タイマー、WakeLockおよびフォアグラウンドサービスを停止・解放する。
- Activityがバックグラウンドへ移行しただけの場合は、測定サービスが所有するBluetoothリソースを解放せず測定を継続する。
- Activityまたはサービスの終了時には、それぞれが所有するリソースを `onDestroy` 等のライフサイクル処理と共通クリーンアップ処理から解放する。
- Bluetooth無効化、権限喪失、例外、接続解除などの異常終了経路でも、通常停止と同じクリーンアップ処理を実行する。

### 4.5 受け入れ条件

- 測定中にホーム画面へ移動してもRSSI取得が継続する。
- バックグラウンド中の測定値が、復帰後のグラフ、統計および保存データに含まれる。
- TARGET探索中にホーム画面へ移動すると、探索だけが即座に停止し、ダイアログと検出済み一覧は保持される。
- アプリへ戻ると、保持された端末選択ダイアログと一覧が表示される。
- フォアグラウンドへ戻っただけではTARGET探索が再開しない。
- 測定値はターゲット応答の受信ごとに追加され、データ点の時間間隔が固定されていない。
- グラフの横軸に `Time [sec]` が表示される。
- 測定停止またはアプリ終了後に、アプリが開始したBluetooth探索、Receiver、WakeLock、タイマー、サービスが残らない。
- リソース解放のために端末のBluetooth自体がOFFにならない。

### 4.6 未決定事項

現時点で、測定実行とライフサイクルに関する未決定事項はない。
